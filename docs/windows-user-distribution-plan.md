# Windows 普通用户分发与使用方案

## 目标

面向普通 Windows 用户提供一套低门槛的下载安装体验，让用户完成下面这条链路：
1. 下载 `Setup.exe`
2. 双击安装
3. 打开桌面应用
4. 选择音频文件
5. 开始生成字幕

用户不需要理解或手动处理下面这些概念：
- Python
- ffmpeg
- 环境变量
- PATH
- Conda
- 命令行

## 首版交付形态

首版采用 `Windows 安装包 + Electron 桌面应用 + 内置运行时` 的方式交付。

安装包内置：
- Electron 桌面程序
- Python 运行时
- ffmpeg
- Python 后端脚本
- Python 依赖
- `.env.example` 模板

安装包不内置：
- Whisper 模型文件

Whisper 模型在首次真正执行任务时自动下载到用户数据目录。

## 目录分层

安装态必须明确区分只读程序目录和可写用户目录。

### 安装目录

只放程序本体，典型位置在 Electron 安装目录下：
- Electron 主程序
- `resources/app.asar` 内的前端代码
- `resources/runtime/backend/` 下的 Python 后端文件
- `resources/runtime/python/` 下的内置 Python
- `resources/runtime/tools/ffmpeg/` 下的 ffmpeg

### 用户数据目录

统一使用 `app.getPath("userData")` 对应的每用户目录，承载所有可写内容：
- `.env`
- `output/`
- `runtime/cache/`
- `runtime/temp/`
- Whisper / HuggingFace 缓存
- 日志

这样做的目的有两个：
- 安装到 `Program Files` 后不会因为写权限失败
- 升级安装包时不会误覆盖用户输出和模型缓存

## 推荐分发策略

### 1. 安装包形态

首版固定采用 `electron-builder + NSIS` 生成标准 `Setup.exe`。

不做：
- 绿色版
- MSI
- Microsoft Store
- 自动更新

推荐原因：
- 更符合普通 Windows 用户的安装习惯
- 可以自动创建桌面快捷方式和开始菜单入口
- 出现问题时也更容易让用户按“重装应用”的思路处理

### 2. 运行时策略

所有运行时依赖都由应用自带，不依赖系统环境。

原则如下：
- 不要求系统已安装 Python
- 不要求系统已安装 ffmpeg
- 不要求用户修改系统 PATH
- 不要求用户手动创建缓存目录

### 3. 模型策略

Whisper 模型不打进安装包，改为首次运行时自动下载。

优点：
- 安装包体积更可控
- 发布和更新更轻
- 后续模型策略调整更灵活

需要配套的用户提示：
- 首次运行可能较慢
- 首次运行需要联网下载模型
- 下载完成后自动继续任务

### 4. 更新策略

首版采用“重新下载安装包覆盖安装”的策略，后续再考虑自动更新。

这样可以把首版重点放在：
- 能安装
- 能启动
- 能执行原文模式
- 在无系统 Python、无系统 ffmpeg 的环境下也能运行

## 构建与发布命令

项目内的标准命令应固定为：

```bash
npm run build:runtime
npm run dist:win:dir
npm run dist:win
```

含义如下：
- `build:runtime`：组装 `.runtime-build/`，包含后端脚本、内置 Python、内置 ffmpeg
- `dist:win:dir`：生成 `dist/win-unpacked/` 供本地烟测
- `dist:win`：生成正式 NSIS 安装包 `Setup.exe`

## 首次运行流程

首版建议把首次使用体验拆成四个阶段。

### 阶段 1：启动自检

应用启动后先检查：
- 内置 Python 是否可用
- 内置 ffmpeg 是否可用
- 输出目录是否可写
- 基础配置是否齐全

前台只展示用户友好的结果，不直接暴露底层路径和堆栈。

推荐文案：
- “应用环境已就绪”
- “应用环境异常，请重新安装应用”

### 阶段 2：用户填写任务参数

用户完成：
- 选择音频文件
- 选择字幕模式
- 译文 / 双语时填写翻译场景

这个阶段不应出现技术术语。

### 阶段 3：首次模型检查与下载

用户第一次真正点击开始任务时，如果模型不存在：
- 明确提示这是首次运行的正常流程
- 提示需要联网
- 显示下载中状态
- 下载完成后自动继续任务

推荐文案：
- “首次运行需要下载语音模型”
- “正在下载模型，请保持网络连接”
- “模型下载完成，正在继续处理”

### 阶段 4：正常任务处理

模型准备完毕后，进入常规流程：
- 识别
- 翻译
- 导出

这个阶段主界面重点展示阶段状态、日志和结果预览，不再让用户关心环境问题。

## 错误提示策略

普通用户版本最重要的是不要直接把底层错误当主文案展示。

推荐采用两层错误展示。

### 第一层：用户可理解提示

作为主错误文案，例如：
- “首次模型下载失败，请检查网络后重试”
- “当前音频文件无法读取，请重新选择文件”
- “应用环境异常，请重新安装应用”

### 第二层：技术详情

放在“查看详情”或日志里，例如：
- Python 异常堆栈
- `stderr` 原文
- 运行时路径信息

这样既方便排障，也不会吓到普通用户。

## 下载页和安装说明建议

下载页内容尽量简洁，只保留必要信息：
- 产品一句话说明
- 一个主下载按钮
- 支持的系统版本
- 首次运行会自动下载模型的提示
- 常见问题入口

安装说明建议压缩到 3 步：
1. 下载 `Setup.exe`
2. 双击安装并按提示完成
3. 从桌面快捷方式打开应用

不要让安装说明出现这些内容：
- 安装 Python
- 安装 ffmpeg
- 配置环境变量
- 打开命令行
- 手动复制模型文件

## FAQ 建议

### 为什么第一次运行比较慢？

因为应用第一次真正处理任务时会自动下载语音模型，完成后后续速度会稳定很多。

### 为什么第一次运行需要联网？

因为首次需要下载模型文件，下载完成后通常不需要重复下载。

### 安装后打不开怎么办？

优先建议重新安装；如果仍失败，再查看错误详情并反馈给开发者。

### 为什么处理失败？

常见原因包括音频文件损坏、首次模型下载失败、网络异常或翻译配置缺失。

### 升级版本会不会丢数据？

只要继续把输出、缓存和模型保存在用户数据目录，重新安装新版通常不会影响已有输出文件。

## 发布前检查清单

发布前至少确认下面这些项目：
- `.runtime-build/` 已成功生成
- `dist:win:dir` 成功
- `dist:win` 成功
- 安装包可正常安装和卸载
- 无系统 Python / 无系统 ffmpeg 的环境下仍可运行
- 原文模式可完成一次完整任务
- 译文模式保存设置后重启仍生效
- 输出文件写入用户目录，不会写入安装目录
- “打开文件 / 打开目录 / 复制路径” 在安装版中正常
- 前台错误文案不直接暴露堆栈

## 结论

面向普通 Windows 用户的首版最佳方案是：
- 提供标准 `Setup.exe`
- 内置 Python、ffmpeg 和 Python 后端依赖
- 把可写数据统一放到用户数据目录
- 首次运行时自动下载模型
- 暂时采用人工出包与人工上传

这套方案的核心目标，是把复杂性收进应用内部，让用户感受到的是“下载、安装、打开、使用”，而不是“先搭环境再运行工具”。
